# Forge Theory Suite
### One Ecosystem. Many Forges. Unified Semantics.

Forge‑Theory‑Suite is the canonical home of all Forge‑class systems in the Forge‑Theory‑Labs ecosystem.  
It consolidates every cognitive forge, simulation forge, and robotic forge into a single, coherent, human‑navigable structure.

Forge Theory itself is a framework demonstrating how universal mathematical and structural patterns appear across domains — from cognition to simulation to embodied robotics.  
This suite organises the engines that express those patterns.

---

## 📦 Repository Purpose

This repository acts as the container for all Forge‑class engines:

- Cognitive forges  
- Simulation & emergence forges  
- Robotic forges  

Each forge is injected into a clean, typed directory structure, removing redundant metadata and preserving only the meaningful semantic core of each project.

This repo is not a monorepo of code; it is a semantic suite — a structured, curated collection of engines that share a common design philosophy.

## 🧩 Philosophy

All forges share three invariants:

1. Deterministic behaviour  
2. Minimal dependencies  
3. Semantic clarity  

The suite enforces these invariants by:

- Removing redundant metadata  
- Normalising documentation into \`capsule.md\`  
- Providing suite‑level governance (CONTRIBUTING, SECURITY, LICENSE)  
- Ensuring consistent structure across all engines  

---

## 📘 Documentation Model

Each forge contains:

- \`capsule.md\` — the forge’s identity, purpose, and semantics  
- \`index.html\` or equivalent — interactive demos where applicable  
- Source files — the forge’s core logic  

Suite‑level documentation lives at the root:

- README.md (this file)  
- CONTRIBUTING.md  
- SECURITY.md  
- LICENSE  

---

## 🔧 Maintenance & Governance

All forges follow the same governance rules:

- No external dependencies unless justified  
- No global mutable state  
- No ambiguous interfaces  
- No unsafe behaviours (robotics)  
- No unbounded growth (simulation)  
- No secrets or credentials  

These rules are enforced suite‑wide.
