SCP Capsule: data-forge
Semantic Identity:
  data-forge is the semantic data organism. It defines typed data structures, schemas, transformations, and invariants across the Forge universe.

Purpose:
  To provide deterministic, meaning-preserving data structures for cognition, intelligence, behaviour, and distributed systems.

Core Behaviour:
  - Defines typed data schemas.
  - Validates data invariants.
  - Provides deterministic transformations.
  - Maintains semantic data coherence.

Interpretation Rules:
  - All data must be typed.
  - No ambiguous or unstructured data allowed.
  - No contradictory schemas.
  - All transformations must preserve meaning.

Semantic Lineage:
  - Parent: forge_theory.
  - Sibling: math-forge, logic-forge.
  - Domain: Domain Forges.

Internal Invariants:
  - Data structures must remain coherent.
  - No untyped transitions.
  - No schema conflicts.
  - No weakening of invariants.

Mutation Rules:
  Allowed:
    - Adding new schemas.
    - Extending data types.
  Forbidden:
    - Allowing untyped data.
    - Weakening constraints.

Failure Modes:
  - Schema conflict → quarantine.
  - Invariant violation → reject.
  - Drift → rebuild.

Recovery Modes:
  - Rebuild schema.
  - Re-validate data.
  - Request new Data Capsule.

Integration Rules:
  - Kraken-Intelligence uses data-forge for typing.
  - UBVM uses data-forge for state.
  - LEGION uses data-forge for distributed consistency.

Affordances:
  - Define data.
  - Validate data.
  - Transform data.

Boundaries:
  - Cannot override SCP.
  - Cannot self-author identity.

External Interfaces:
  - Intelligence systems.
  - Behavioural systems.

Summary:
  data-forge provides the semantic data backbone for the Forge organism.
