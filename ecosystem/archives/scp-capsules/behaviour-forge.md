SCP Capsule: behaviour-forge
Semantic Identity:
  behaviour-forge is the semantic behaviour construction organism. It builds, validates, transforms, and optimises Behaviour Capsules across the Forge ecosystem.

Purpose:
  To ensure that all behaviours — whether human‑authored, cognitively generated, or system‑derived — remain coherent, typed, deterministic, and SCP‑compliant.

Core Behaviour:
  - Constructs behaviour graphs from primitives.
  - Validates behavioural invariants.
  - Optimises behaviour graphs for UBVM execution.
  - Transforms behaviours while preserving meaning.

Interpretation Rules:
  - All behaviours must be typed.
  - No behaviour may violate SCP meaning.
  - Behaviour graphs must remain deterministic.
  - No untyped transitions allowed.
  - Behaviour conflicts must be resolved before execution.

Semantic Lineage:
  - Parent: ScriptForge and mind‑forge.
  - Sibling: UBVM (execution).
  - Child: Behaviour Capsules.
  - Domain: Behavioural Layer.

Internal Invariants:
  - Behaviour graphs must remain valid.
  - No contradictory behaviours allowed.
  - All nodes must map to UBVM primitives.
  - No loss of meaning during optimisation.
  - Behaviour invariants must remain intact.

Mutation Rules:
  Allowed:
    - Adding new behaviour primitives.
    - Extending optimisation strategies.
    - Improving validation heuristics.
  Forbidden:
    - Weakening SCP constraints.
    - Allowing ambiguous behaviours.
    - Modifying core behaviour semantics.

Failure Modes:
  - Invalid behaviour → reject.
  - Invariant violation → quarantine.
  - Graph conflict → request clarification.
  - Optimisation failure → fallback to raw behaviour.

Recovery Modes:
  - Rebuild behaviour graph.
  - Re‑validate behaviour.
  - Reconstruct behaviour from primitives.
  - Request new Behaviour Capsule.

Integration Rules:
  - UBVM executes behaviour‑forge outputs.
  - ScriptForge and mind‑forge feed behaviours into behaviour‑forge.
  - LEGION distributes validated behaviours.
  - All behaviours must be SCP‑compliant.

Affordances:
  - Build behaviour.
  - Validate behaviour.
  - Optimise behaviour.
  - Transform behaviour.
  - Inspect behaviour graphs.

Boundaries:
  - Cannot execute behaviours.
  - Cannot override SCP.
  - Cannot self‑author identity.
  - Cannot generate behaviours without input.

External Interfaces:
  - UBVM Execution Engine.
  - ScriptForge Compiler.
  - mind‑forge Cognitive Layer.
  - Semantic State Bus.

Summary:
  behaviour‑forge is the semantic behaviour construction engine — ensuring that every behaviour in the Forge organism is coherent, typed, deterministic, and meaning‑preserving.
